トイ・トランスフォーマー実験室

「前者」はどうやって「イヌ」に辿り着くのか

埋め込みを10次元に増やし、「第一要素らしさ・第二要素らしさ」という経路(ルーティング)用の次元と、 「イヌらしさ・ネコらしさ」という中身(コンテンツ)用の次元を、はっきり別の軸として持たせました。 経路の次元は単語自体の性質ではなく文中の位置から決まるので、まずは文脈に依らない静的な埋め込みと、 位置から後付けされるロールとを分けて見られるようにしています。

07 Attention ここまでの流れ

トークン埋め込みは文脈非依存
「イヌ」というトークンの語彙表由来の埋め込みは、文中のどこにあっても常に同じ。item-1らしさのような位置に依存する情報は、この段階ではまだ存在しない。
浅い層が位置ロールを書き足す
位置エンコーディングと「AとBが」という並列構文を検出する浅い層が、item-1/item-2次元だけを残差ストリームに追加で書き込む。ここで初めて「文脈化された」ベクトルになる。
経路と中身は別の次元
こうして出来上がった最終ベクトルの中で、「第一要素らしさ/第二要素らしさ」(経路)と「イヌらしさ/ネコらしさ」(中身)は独立した軸として共存している。
Q / K の内積 — 経路の次元だけを見る
この Attention ヘッドの Q・K は経路の2次元しか参照しない。イヌらしさ/ネコらしさの次元は Q・K の内積にはまったく寄与しない。「どこを見るか」は「何が書いてあるか」と切り離されている。
Softmax → 加重和
経路の次元から計算されたスコアを Softmax で重みに変換し、その重みで Value(中身の次元だけを運ぶベクトル)を混ぜ合わせる。
残差ストリームへの加算
混ぜ合わされた Value は「前者」の元のベクトルに上書きではなく足し算される。結果、「前者」の"イヌらしさ"次元がAttention重みの分だけ立ち上がり、以降の層では「前者 ≈ イヌ」として扱える状態になる。
(この先は FFN の仕事)
どのトークンを見るかを決めるのは Attention の役割。運ばれてきた"イヌらしさ"をどう加工するかは、この後の FFN 層が引き継ぐ。
単純化のための注記: 実際のモデルではこの10次元のような綺麗な専用軸ではなく、多数の特徴が重ね合わさって(superposition)、単一の軸ではなく「方向」としてエンコードされるのが一般的です。また Attention ヘッドは複数あり、経路と中身の分離もここまで明瞭ではないことが多いです。ここでは「ルーティングに使う次元」と「運ばれる中身の次元」が原理的には別物である、という点だけを抜き出して可視化しています。

トイ・トランスフォーマー実験室 — FFN 編

「フランスの首都は？」はどうやって「パリ」に辿り着くのか

今回はAttentionではなくFFNです。FFNを「たくさんのニューロンからなるKey-Valueメモリ」とみなす見方 (Geva et al., 2020)に沿って、各ニューロンが「国」と「話題」の組み合わせを検出するKeyを持ち、 条件が揃うとReLUで発火して、対応するValue(その都市らしさ)を残差ストリームに書き込む様子を再現しました。

01 FFN 設定を動かしてみる

質問の「国」と「話題の強さ」、そしてニューロンの学習度(閾値の鋭さ)を変えて、どのニューロンが発火するか観察してください。

質問されている国

02 FFN 計算パイプライン全体図

入力ベクトル x が3つのニューロンすべてに渡ります。各ニューロンは独立に Key・x − しきい値 を計算し、ReLU を通過した分だけ自分の Value を残差に加算します。Attentionと違って、ニューロン同士は競合しません(softmaxがない)。一番上のグレーの箱は、この入力 x を作った前段のAttention層の位置を示すためだけのもので、ここでは計算していません。

03 FFN 発火の様子だけを拡大

上の図の「Key・x → ReLU」の部分だけを取り出したものです。入力 x から3本の矢印が伸び、太さと濃さがそれぞれのニューロンの発火度を表します。

04a FFN 静的トークン埋め込み(語彙表由来)

「フランス」「首都」というトークンそれぞれの埋め込みです。この段階では、まだ1つの位置に合成されていません。並び順ではなく国を選び直しても、単語自体の埋め込みの形は変わりません。

04b FFN 前段の Attention による集約(浅い層)

FFNは1つの位置のベクトルしか見られません。なので前段のAttention層が、「フランス」と「首都」、それぞれのトークンの特徴をあらかじめこの位置にコピーしてきます。イヌ/ネコの例で見た「浅い層が位置ロールを書き込む」のと同じ発想です。

04c FFN 深い層(FFN)に渡される最終ベクトル(=04a + 04b)

2つのトークンの特徴が1つの位置に集約された結果です。中身(都市らしさ)の次元はまだ全部ゼロ — ここから先、パイプライン図の「Key・Value」の計算に入ります。

05 FFN Key が実際に読んでいる次元

各ニューロンのKeyは、10次元のうち「国」と「トピック」の2つしか見ていません。グレーの行は、値があってもこのニューロンには無視されている次元です。

06 FFN Value の加重和と、残差ストリームへの加算

Keyは「国・トピック」の次元しか見ませんが、Valueは逆にそこを運ばず、「都市らしさ」の次元だけを運びます。ReLUを通った発火度で重み付けしたValueを、入力ベクトルに足し込みます。

07 FFN Attention との違い

競合しない
Attentionの重みはSoftmaxで正規化され、複数の候補が重みを奪い合う。FFNのニューロンは独立にReLUを通るだけなので、条件さえ揃えば複数のニューロンが同時に発火してもよい。
ReLUがAND条件を作る
Key・x がしきい値を超えたときだけ発火するので、「国が合っている」だけでも「トピックが合っている」だけでも発火せず、両方揃って初めて発火する — というAND的な振る舞いをしきい値付きの線形和とReLUだけで実現している。
「知識」はニューロンの中に静的に眠っている
Attentionは文中の他のトークンを動的に参照するのに対し、FFNのKey・Valueのペアは学習時に固定され、以後は同じ入力パターンには常に同じValueを返す — 事典の索引のような静的な知識の格納庫として働く。
単純化のための注記: 実際のFFN層は数千〜数万のニューロンを持ち、1つの事実が複数のニューロンに重ね合わさって(superposition)分散的に格納されていることが多く、単一のニューロンがきれいに「パリ担当」になっているとは限りません。また実際の閾値はバイアス項として学習され、Keyベクトルも生の埋め込みではなく前段の層で変換された表現に対して働きます。ここでは「Key・x − しきい値 → ReLU → 加重和」という中心的なメカニズムだけを取り出しています。
